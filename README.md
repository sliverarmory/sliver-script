# Sliver Script

Sliver-script is a TypeScript/JavaScript client library for Sliver, it can be used to automate any operator interaction with Sliver. Sliver-script uses existing Sliver client configuration files and connects to servers using gRPC over Mutual-TLS. It also provides [RxJS](https://www.learnrxjs.io/) abstractions for easy interactions with real-time components.

This library targets modern Sliver protobuf/gRPC APIs and provides a strongly-typed TypeScript-first client.

The integrated wrapper provenance is pinned in `integration.lock.json`: standalone base `01f1029cc17898da681e52b64af4a708ff82c3d3`, authoritative Sliver GUI source `f0fa15af24365c9fdab1a2cdff769c88c1ad7cf6`, and Sliver/protobuf source `ca685f5eed64c3327c0e57504928cfd2d2e96bea`. The package exposes explicit typed convenience methods and no method-name/request-object dispatcher. For compatibility it still exports the generated `rpcpb` namespace and the existing statically typed `SliverClient.rpc` getter; trusted applications must impose their own narrower capability boundary, as Sliver GUI does in its main-process adapter.

### Install

Node v24 or later is required for this package, and it can be installed via npm:

`npm install sliver-script`

### WireGuard operator configs

The npm package includes a pinned, self-contained Go module for the local WireGuard transport helper. Set `wg.enabled` to `true` to opt into the WireGuard wrapper; an absent or false value keeps the normal direct mTLS connection. On first enabled use, sliver-script builds a process-private helper from those packaged sources under the operating-system temporary directory and removes that binary when the Node.js process exits. This fallback requires Go 1.24 or newer and network access to populate the Go module cache.

WireGuard public keys, private keys, and the optional preshared key must each be nonzero and exactly 64 hexadecimal characters. Client and server tunnel addresses must be bare IPs or host-length `/32` or `/128` prefixes from the same address family; whitespace, zones, mapped addresses, non-host prefixes, line breaks, and WireGuard directive injection are rejected before the helper starts. A nonzero preshared key also requires matching server-side support; pinned stock Sliver does not currently configure a multiplayer-server PSK, so that field is intended for compatible custom or future servers.

Set `SLIVER_SCRIPT_WG_PROXY_BINARY` to the absolute path of a trusted, prebuilt helper to skip the source build. The configured path must be a regular file, not a symbolic link. Bundled applications, whose packaging can erase the library's package-relative source location, must supply this absolute override. Development and CI validate the packaged helper module with `npm run helper:check` and exercise the installed source-build/start/stop path with `npm run pack:check`.

> [!WARNING]
> Version 2.0.0 is not publish-ready yet. The direct-mTLS 20 MiB response control passes, but the same required server-to-operator transfer currently stalls and times out through the operator WireGuard helper. The full Linux and macOS E2E gate remains enabled and intentionally blocks publication until that transport defect is fixed.

### Reproducible protobuf generation

Generated TypeScript under `src/pb` is locked to Sliver commit `ca685f5eed64c3327c0e57504928cfd2d2e96bea`, protoc 35.1, and ts-proto 2.11.4. The generator reads only the pinned `sliver` submodule; it never selects a neighboring checkout.

From a Git source checkout, install protoc 35.1 after `npm ci`, initialize the pinned submodule, and run:

```sh
git submodule update --init --recursive
npm run protobuf:check
```

`npm run protobuf:generate` rewrites the five checked-in protobuf modules only after the source commit, source tree, input hashes, descriptor hash, generator version, and generated byte hashes all match `protobuf.lock.json`.

That command is restorative, not an upgrade command. Advancing Sliver, protoc, or ts-proto requires a deliberate maintainer review that regenerates and updates every source, descriptor, and output hash in the lock together.

The npm tarball carries those generated TypeScript modules and their provenance lock, but deliberately excludes the Sliver submodule and therefore is not a self-contained protobuf regeneration checkout.

Before preparing a package, run `npm run audit:all` and `npm run verify`. The full audit covers the publication toolchain; verification separately audits the exact packed runtime dependency graph, then executes unit tests, protobuf and WireGuard-helper checks, a clean TypeScript build, `npm pack --dry-run`, and CommonJS, ESM, TypeScript NodeNext, and installed WireGuard-helper smoke tests against the packed tarball in a temporary consumer. The published tarball includes the TypeScript source and locked protobuf provenance in addition to compiled JavaScript, declarations, and the helper's Go module source.

Publishing is tag-only: the workflow requires a GitHub-verified, signed annotated `vMAJOR.MINOR.PATCH` tag (optionally with a SemVer prerelease) whose target and version match both package metadata files. It reruns the full cross-platform package and E2E gate, verifies one retained release tarball, and publishes those exact bytes through npm trusted publishing with OIDC and provenance; stable versions use the `latest` dist-tag while prereleases are kept off `latest`. After publication, the workflow independently installs the exact registry artifact, verifies its SRI and dist-tag, runs npm's attestation audit, and re-verifies the SLSA bundle with the pinned Sigstore implementation against the exact repository, workflow, tag, commit, GitHub IDs, run, and publishing environment.

Before the first release, configure the `sliver-script` package's npm trusted publisher for GitHub repository `sliverarmory/sliver-script`, workflow filename `publish.yml`, environment `publish`, and direct `npm publish` permission. The workflow deliberately has no long-lived npm publish token fallback.


### TypeScript Example

#### Basic

```typescript
import { SliverClient, ParseConfigFile } from 'sliver-script'

(async function() {
    
    const config = await ParseConfigFile('./localhost.cfg')
    const client = new SliverClient(config)

    await client.connect()

    const version = await client.getVersion()
    console.log(version)

    const sessions = await client.sessions()
    console.log(`Sessions: ${sessions.length}`)

    await client.disconnect()

})()
```

#### Monitor Events in Real-time

```typescript
import { SliverClient, ParseConfigFile } from 'sliver-script'

(async function() {

    const config = await ParseConfigFile('./localhost.cfg')

    const client = new SliverClient(config)
    await client.connect()
    client.event$.subscribe((event) => {
        console.log(event)
    })

})()
```

#### Automatically Interact with New Sessions

```typescript
import { SliverClient, ParseConfigFile } from 'sliver-script'


(async function() {

    const config = await ParseConfigFile('./localhost.cfg')
    const client = new SliverClient(config);
    await client.connect()

    console.log('Waiting for new sessions ...')
    client.session$.subscribe(async (event) => {
        console.log(`New session #${event.Session.ID}!`)
        const session = client.interactSession(event.Session.ID)
        const ls = await session.ls('.')
        console.log(`Path: ${ls.Path}`)
        ls.Files.forEach(file => {
            console.log(`Name: ${file.Name} (Size: ${file.Size})`)
        })
    })

})()
```

### JavaScript Example

```javascript
const sliver = require('sliver-script');

;(async function() {

    const config = await sliver.ParseConfigFile('./localhost.cfg')
    const client = new sliver.SliverClient(config)
    await client.connect()

    console.log('Waiting for new sessions ...')

    client.session$.subscribe(async (event) => {

        console.log(`New session #${event.Session.ID}!`)

        const session = client.interactSession(event.Session.ID)
        const ls = await session.ls('.')
        console.log(`Path: ${ls.Path}`)
        ls.Files.forEach(file => {
            console.log(`Name: ${file.Name} (Size: ${file.Size})`)
        })
        
    })

})()
```
